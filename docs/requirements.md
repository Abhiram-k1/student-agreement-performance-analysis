**ASSIGNMENT 1: SCALA PROGRAMMING AND DISTRIBUTED DATA PROCESSING USING RDDS**

**Title:** Student Academic Performance Analysis Using Apache Spark RDDs

**Scenario:** A university maintains academic records of students across multiple departments. The university wants to analyse student performance using distributed data processing techniques.

**Tasks to be performed:**

1. Create a Scala application and define an entity class named Student with attributes such as Student ID, Name, Department, Semester, and Marks.
2. Create multiple Student objects and convert the collection into an RDD.
3. Perform the following RDD operations:
   - Display all student records.
   - Filter students who scored more than 75 marks.
   - Calculate the total number of students in each department.
   - Calculate the average marks of students.
   - Identify the student with the highest marks.
4. Demonstrate the difference between RDD transformations and actions using appropriate operations.
5. Execute multiple transformations and observe Spark's lazy evaluation behaviour.
6. Examine the DAG generated by Spark for the implemented operations.
7. Explain how Spark distributes the processing tasks across the cluster.

## Ambiguities and decisions

- No dataset is prescribed. UCI dataset 697 is selected because it provides genuine higher education records, course groupings and semester grades with a redistribution license.
- The source is anonymous. Student IDs and names are stable source-row display labels. Course code is used as the available grouping proxy for Department. The mapping is disclosed in the dataset documentation.
- The screenshot uses a 75-mark threshold without giving a mark scale. The source uses 0–20 grades, so the documented conversion to a 0–100 scale preserves the measured information.
- The default is first-semester performance. A `--semester 2` acquisition option supports the other measured semester.
- Students with no evaluations are omitted. Positive-evaluation records with a zero grade remain included.
- If multiple semester rows are supplied later, department counts count unique StudentID values. Averages use semester observations.
- The maximum can have ties. Every tied record is reported so the result remains complete.
- No cluster infrastructure is prescribed. Local Spark executes and exposes partitions/stages/tasks. Standalone-cluster submission instructions support distributed execution when a cluster is available.
- DAG inspection requires viewing actual run evidence. The project records event logs and documents how to inspect them. UI observation and cluster screenshots can be completed during the user's execution.
